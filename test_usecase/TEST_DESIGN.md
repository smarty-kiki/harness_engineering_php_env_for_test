# 综合测试设计指南

本指南说明如何从真实使用入口设计测试用例，重点覆盖正常流程之外的失败、数据丢失和可逆操作边界。它属于 harness 的通用方法，不包含任何具体项目的用例或数据。

设计时先问三个问题：

1. **依赖不可用时，用户看到什么、还能做什么？**
2. **底层数据不存在或与页面状态不一致时，操作会怎样？**
3. **可逆操作执行后，能否正确回退，重复执行是否安全？**

## 1. 按入口分层设计

| 入口 | 优先测试内容 | 不适合的场景 |
|------|--------------|--------------|
| 页面 | 用户可见流程、表单校验、提示、按钮状态、跳转、空态、权限表现 | 需要构造大量参数矩阵、直接协议调用、无法通过 UI 触发的异常分支 |
| 接口 | 参数边界、鉴权、状态机、分页、并发/幂等、异常返回、跨资源隔离 | 纯展示效果、页面交互 |
| CLI | 命令参数、退出码、交互确认、批处理、回滚、依赖不可用时的诊断 | 页面展示 |

同一段逻辑优先从页面穿透；页面不可达或难以稳定触发的，再用接口或 CLI 补测。三层用例统一计入通过率，不应把某一层的问题隐藏成“只在前端测不到”。

## 2. 接口不可用 / 异常响应

模拟角度：

- **网络失败**：请求被拒绝、连接中断、超时。
- **服务端错误**：HTTP 500/502/503、业务错误码、非 JSON / 空响应。
- **慢响应**：延迟返回、长时间不返回。
- **鉴权失败**：未登录、会话过期、无权限、Key 被撤销。
- **部分失败**：页面首屏多个接口中一个失败、列表分页中某一页失败、弹窗依赖数据失败。

检查点：

- 不出现**假成功**：不能显示成功 toast、不能把未写入的数据渲染成已保存、不能静默刷新成成功态。
- 错误对用户可见且可理解，不能白屏、无限 loading、弹原生错误框或只留下空页面。
- 操作控件能恢复：按钮解除禁用、表单可重新提交、弹窗可关闭、重试不会重复提交。
- 无未捕获前端异常、无未处理的 Promise、无控制台致命错误。
- 失败后页面仍可继续操作其他功能，不污染已有数据。
- 重复提交 / 重试具备幂等性或明确防重提示。
- 慢响应期间有 loading 或禁用态，避免用户重复点击。

断言应写入用例的 `expected` / `actual`，失败不中断后续用例。

## 3. 底层数据被删除 / 状态不一致

删除时机：

- 页面加载前删除；
- 详情页已经打开后删除；
- 用户点击保存 / 状态流转 / 确认弹窗时删除；
- 关联数据先删除，主数据仍在。

删除对象：

- 主记录（项目、任务、单据等）；
- 关联记录（成员、版本、配置、关联资产）；
- 凭证 / 邀请 / 会话；
- 子表或引用表。

观察点：

- 列表页、详情页、编辑页、历史记录、跨页面入口是否还能正常呈现；
- 旧页面上继续操作时的提示与按钮恢复；
- 是否会误写、误删、串到其他记录；
- 是否泄露不属于当前用户的数据；
- 是否出现白屏、未捕获异常、裸露 SQL / 堆栈；
- 空态或“不存在”错误是否明确；
- 测试数据能否被清理脚本回收。

通用工具 `fixtures/delete_row.php` 可按表名与 ID 物理删除一条记录。项目如有子表或关联级联，应在项目自己的夹具中补充清理，或复制工具后扩展。破坏性用例必须使用专用测试数据，不能碰生产数据。

## 4. 输入数据格式与大小边界

对所有用户可填、接口可传、命令可带的数据，都要同时验证格式、长度和大小边界，不能只测合法值。

### 4.1 格式

- 数值：负数、0（不允许时）、超大值、小数 / 科学计数、数字字符串、空值、`null`、数组 / 对象。
- 标识：非法 ID、负数 ID、0、跨资源 ID、已删除资源 ID。
- 业务格式：版本号、日期、邮箱、URL、分支名、枚举、状态动作。
- 文本：纯空格、前后空格、纯符号、Unicode / 中文 / emoji、换行、HTML / 脚本 / SQL 特殊字符。
- 类型：字符串传数字、数字传字符串、布尔 / 数组 / 对象传标量；JSON 嵌套层级异常。
- 结构：必填缺失、重复字段、未知字段、空数组 / 空对象。

### 4.2 长度

- 空值、纯空格、最小长度、最大允许长度、最大长度 + 1。
- 按字符计数（`mb_strlen`）与按字节计数（数据库列长）分别考虑，中文 / emoji 容易暴露截断。
- 数据库列有长度上限时，超限必须是业务校验错误，不能把 SQL 截断 / `SQLSTATE[22001]` 直接暴露给用户，也不能静默截断后写入。
- 超长文本、超长名称、超长描述、超长 URL / 分支名分开覆盖。

### 4.3 大小与数量

- 请求体过大、单字段过大、列表一次提交过多项。
- 分页参数：负数、0、超大 limit、超大 start_id、翻页越界。
- 批量操作中的部分非法项：应整体拒绝并说明，或明确跳过，不能部分成功后无提示。
- 文件 / 附件：空文件、超大文件、错误 MIME、扩展名与实际内容不一致。

### 4.4 期望行为

- 非法输入应返回明确的业务校验错误，不能返回成功、静默修正、静默截断或原始数据库错误。
- 页面应显示可理解的提示，表单 / 按钮恢复，不能产生假成功或未捕获异常。
- 合法边界值（恰好等于最大长度等）应正常通过；非法值不应写入任何数据。
- 错误信息不应泄露 SQL、堆栈、内部表名等实现细节。
- 输入边界用例同样按边界清单设计，不以覆盖率作为锚点，全部计入通过率。

## 5. 可逆操作与回滚

需要覆盖的可逆/回滚角度：

- 数据库迁移的 `rollback`、批次回滚、重置；
- 批量导入 / 数据修复的回退；
- 版本回退、发布撤销、软删除恢复；
- 队列任务的暂停、恢复、重放；
- 配置变更的撤销。

验证点：

- 正向操作产生的结构 / 数据确实被撤销；
- 追踪记录（批次、版本号、审计日志）同步清理或标记；
- 依赖对象一起恢复，不留下半完成状态；
- 连续执行两次是安全的空操作，或给出明确错误；
- 回滚中途失败时保留诊断信息、退出码非 0、不静默成功；
- 不触碰主数据；使用隔离项目副本 + 临时数据库 / 命名空间。

通用工具 `fixtures/rollback_probe.sh` 展示了隔离回滚验证：复制项目、创建临时数据库、执行真实 `migrate:rollback`、检查 down SQL 与批次记录，并再次回滚验证幂等。其他可逆命令可参考同样的隔离思路。

## 6. 组合场景

单一失败往往不够，应按状态组合扩展：

- 接口失败 + 数据已被删除；
- 重试 + 数据状态已变化；
- 多用户 / 不同权限 + 资源被删除；
- 删除关联数据 + 旧页面继续操作；
- 慢响应 + 重复点击；
- 回滚 + 依赖服务不可用。

组合场景的目标是发现状态不一致、假成功、卡死和越权，而不是堆叠无关步骤。

## 7. 用例记录与统计

- 一个可观察行为对应一条用例；名称写清业务动作和边界，例如“删除后再次提交”“接口失败后可重试”。
- 失败 / 未执行用例必须记录 `expected` 与 `actual`；未执行也计入通过率分母。
- 不在报告里另设“已知问题”区；问题就是失败用例。
- 破坏性用例通常无法用代码覆盖率锚定，应以边界清单驱动设计；但仍纳入全量通过率，覆盖率只作为整体参考。
- 每个用例清理自己造出的数据；无法清理时要在报告中明确。

## 8. 安全与隔离

- 只在测试环境执行，使用专用测试账号与专用测试项目。
- 不修改生产数据，不执行无法恢复的破坏性命令。
- 回滚、迁移、批处理优先在隔离副本 / 临时数据库执行。
- 删除工具、回滚探针等通用脚本的参数与目标必须显式，禁止默认指向主数据库。
- 测试结束执行清理，避免残留影响下一轮。

## 9. 设计检查清单

- [ ] 正常路径是否有一条页面穿透用例？
- [ ] 页面不可达的参数 / 权限 / 状态分支是否有接口或 CLI 用例？
- [ ] 接口失败、超时、非 JSON、鉴权失败各覆盖到没有？
- [ ] 负数 / 0 / 超大数字 / 非法 ID 是否验证？
- [ ] 空值、纯空格、最大长度、最大长度 + 1、中文 / emoji 长度是否验证？
- [ ] 非法格式（版本号 / 日期 / 邮箱 / URL / 分支名 / 枚举）是否拒绝？
- [ ] 超长字段是否返回业务错误而不是数据库原始错误或静默截断？
- [ ] 操作失败后按钮、表单、弹窗、loading 是否恢复？
- [ ] 页面打开前 / 后删除底层数据的行为是否验证？
- [ ] 关联数据删除、跨项目 / 跨用户数据隔离是否验证？
- [ ] 可逆命令是否验证撤销结果、追踪记录和二次执行？
- [ ] 删除 / 回滚是否在隔离环境，是否有清理？
- [ ] 失败用例是否记录期望与实际，是否计入通过率？
